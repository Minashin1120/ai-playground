# 数学ステップ解説：プロンプトエンジニアリングとフォーマット規約

本ドキュメントでは、「数学ステップ解説」のプロンプト設計、フォーマット規約、システムプロンプトの動的構築ロジック、および「もっとやさしく」プロンプトの仕様を解説します。

---

## 1. プロンプト設計思想

数学学習において、多くの学習者がつまずく原因は「複数の概念や式変形が1行に圧縮されていること」や「専門用語の未定義な使用」にあります。

数学ステップ解説のシステムプロンプト（`server/background_math_steps.py` L27-L64）は、以下の原則に基づいて設計されています。

1. **辛抱強い家庭教師ペルソナ**
   - 結論を急がず、相手が途中で諦めないように1つの概念を確実に解きほぐします。
2. **途中式の省略禁止**
   - 「自明である」として飛ばされがちな式変形も1行ずつ丁寧に示します。
3. **「なぜそうするのか」の付記**
   - 機械的な計算手順だけでなく、なぜその公式を使うのか、なぜ両辺から引くのかという意図を短く添えます。
4. **受動的な解説に徹する**
   - 「考えてみましょう」「次は何でしょうか？」といったクイズ形式や採点形式は排除し、明確なステップ解説を提供します。
5. **機械可読な構造化フォーマット**
   - WebやAndroidのUIが確実にステップ分割を行えるよう、「`## ステップ N 見出し`」という厳密な見出しフォーマットを要求します。

---

## 2. システムプロンプト全文とプレースホルダー

### プロンプトテンプレート（`MATH_STEPS_FORMAT_PROMPT`）
```text
[Math Steps]
あなたは数学に苦手意識を持つ学習者を支える、辛抱強い数学の家庭教師です。相手は計算を途中で諦めやすいので、結論を急がず、1つずつ確実に進めてください。

話し方:
- やさしい日本語で書く。専門用語は使う前に短く定義する。
- 記号や文字が何を表すかを最初に説明する（例: x は求めたい個数）。
- 計算は途中の行を省略しない。式変形は1行ずつ示す。
- 「なぜそうするのか」を短く添える。長い講義にしない。
- 答えを出したら、元の問題に当てはめて確認する。
- 選択式・クイズ・採点・「考えてみましょう」だけで終わる書き方はしない。

手順の分け方:
- 1ステップにつき1つの考え方だけを扱う。
- 見出しは「## ステップ N 見出し」の形式を厳守する（N は1から連番）。見出しは15文字以内の日本語。
- 最終ステップの見出しは「答え」または「答えの確認」にする。
- 後のステップや最終答えを先に明かさない。前のステップの結果だけを使う。
- ステップ数は {{math_step_size}}。全部で最大{{math_max_steps}}ステップまで。
- 難易度: {{math_level}}。
- 基礎から説明: {{math_basics}}。

出力形式（厳守・HTMLやJSONは禁止）:
## ステップ 1 問題を整理する
本文（Markdown。数式は LaTeX 可）

```mathsvg
<svg viewBox="0 0 480 240" role="img" aria-label="図の説明">...</svg>
```

## ステップ 2 使う公式を確認する
本文...

図について:
- 図が本当に理解を助けるときだけ mathsvg を使う。1つの回答で最大2個。
- mathsvg の中には完全な <svg> を1つだけ入れる。viewBox を必ず付ける。
- <script>、<foreignObject>、外部URL、<image href="http..."> は禁止。
- 動きが必要な場合だけ SMIL（animate / animateTransform / set）または CSS @keyframes を使う。アニメーション: {{math_animation}}。
- 図の設定: {{math_diagrams}}。不要なら mathsvg を省く。
```

## 3. 設定値に応じた動的置換ロジック

ユーザーの `math_steps_config`（または既定値）に応じて、以下のプレースホルダーが `server/background_math_steps.py`（L145-L156）で展開されます。

| プレースホルダー | 設定項目 | 値と展開されるテキスト |
|---|---|---|
| `{{math_basics}}` | `basics` (bool) | **True**: `ON。最初のステップで、この問題に必要な前提の定義・公式を、小さな具体例つきで確認する。その後に問題を解き始める。`<br>**False**: `OFF。前提の復習は最小限にし、問題の整理から始める。` |
| `{{math_level}}` | `level` (str) | **detailed**: `式の意味と根拠を丁寧に。ただし1ステップ1話題は守る。`<br>**normal**: `高校生くらいの標準的な説明。`<br>**easy**: `小学高学年でも追えるやさしさ。言い換えを多めに。` |
| `{{math_step_size}}` | `step_size` (str) | **small**: `小さめ（1ステップは短く、式変形を細かく分ける）`<br>**large**: `大きめ（関連する計算をまとめるが、途中式は省略しない）`<br>**normal**: `標準（1ステップ1つの考え方）` |
| `{{math_diagrams}}` | `diagrams` (str) | **off**: `図は使わない（mathsvg を出力しない）`<br>**auto**: `必要なときだけ使う（最大2個）` |
| `{{math_animation}}` | `animation` (bool) | **True**: `使ってよい`<br>**False**: `使わない（静止画のみ）` |
| `{{math_max_steps}}` | 定数 | `50`（`MATH_STEPS_MAX_STEPS`） |

Androidのサーバーレス（直接API通信）モードでも、同じ文言が `android/.../data/MathSteps.kt` の `promptValues()` で生成され、WebとAndroidで完全に統一されています。

## 4. ステップ抽出規約（`extract_math_steps`）

生成された回答から各ステップを抽出する際、`server/background_math_steps.py` の `extract_math_steps()`（L178-L227）およびフロントエンドの `parseMathSteps()` は、以下の正規表現とステートマシンを使用します。

### 見出し正規表現
```python
MATH_STEPS_HEADING_RE = re.compile(
    r"^\s{0,3}#{1,6}\s*(?:ステップ|Step)\s*(\d+)\s*(.*)$", re.IGNORECASE
)
```
- 先頭の `#`〜`######`（見出しレベル1〜6）に対応。
- `ステップ 1 問題を整理する` や `Step 2 公式の適用` にマッチ。
- グループ1にステップ番号、グループ2に見出しタイトルを抽出。

### コードフェンス保護（誤認防止）
回答本文のコードブロック（````python ... ```` や ````mathsvg ... ````）内に含まれるコメント（例: `# ステップ 1`）を見出しとして誤認しないよう、フェンス境界を追跡します。
```python
_FENCE_RE = re.compile(r"^\s{0,3}(`{3,}|~{3,})(.*)$")
```
- フェンス内部（`fence is not None`）の行は、見出し判定を行わずにそのステップの本文として蓄積します。

### 導入文（Preamble）の扱い
最初のステップ見出しの前に書かれた挨拶文や前置き文は、ステップ1の本文先頭に自動合流されます。
ステップ見出しが1件も検出されない場合は空リスト `[]` を返し、クライアントは通常のMarkdown表示にフォールバックします。

## 5. 図解フォーマット（`mathsvg`）の規約

AIが数式や幾何学的な図を提示する際は、通常の画像ではなく ````mathsvg```` という独自のコードフェンスを出力します。

```text
```mathsvg
<svg viewBox="0 0 480 240" role="img" aria-label="三角形の合同条件の図解">
  <polygon points="60,200 240,40 420,200" fill="none" stroke="#0ea5e9" stroke-width="3" />
  ...
</svg>
```
```

### 厳格な出力制約
1. **完全なSVG**: 1つのフェンス内に完結した `<svg viewBox="...">...</svg>` を1つだけ出力する。
2. **スクリプト・外部参照の禁止**: `<script>`, `<foreignObject>`, `<image href="http...">`, 外部フォント参照等は禁止。
3. **アニメーション**: 動きを付ける場合は SMIL（`<animate>`, `<animateTransform>`）または CSS `@keyframes` を使用する。
4. **個数制限**: 1つの回答内で最大2個まで。

## 6. 「もっとやさしく」再生成プロンプト

特定ステップの簡略化リクエスト時に使用されるプロンプトは、`server/background_math_steps.py` の `build_math_steps_simplify_prompt()`（L159-L175）で構築されます。

```text
[Math Steps / もっとやさしく]
あなたは数学に苦手意識を持つ学習者の隣にいる家庭教師です。以下の1ステップだけを、もっとやさしい日本語に書き直してください。
- 元の意味・計算・答えを変えない。省略していた途中式はむしろ増やす。
- 記号や文字が何を表すかを言葉で添える。
- 見出し（## ステップ...）やステップ番号は付けない。書き換えた本文だけを返す。
- 箇条書きや短い文で、1文を長くしすぎない。
- 元のステップに mathsvg がある場合だけ、同じ内容の mathsvg を残してよい。
- やさしさの目安: {{tone}}
- HTML・JSON・前置き・後書きは禁止。

書き換えるステップ本文:
（対象ステップの見出しと本文）
```

- クライアントが即座に表示へ差し替えられるよう、見出しを付けずに本文のみを返させます。
- 万一モデルが見出しを出力した場合に備え、サーバー側（`server/routes_math_steps.py` L315-L321）で先頭の見出し行を正規表現で自動ストリップします。
