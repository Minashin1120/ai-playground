# V4.8.700 (2026-08-03)

## ボット検出の Turnstile 回避対策（検出の抜けを封鎖）

ユーザー指摘により、Turnstile トークンを取得できないクライアントはテレメトリ報告が一切送られず、ボット検出・BAN を回避できる設計上の穴を修正しました。以下の2点を実装しています。

### 1. トークンが取得できない非管理者は送信をブロック

- ボット検出が有効（`globalEnabled` かつ `accountEnabled` かつ非管理者）のユーザーは、メッセージ送信時に `getTurnstileToken()` でトークンの取得を試みます。
- トークンが取得できない場合（Turnstile スクリプト遮断、widget エラー、解決不能など）は送信をブロックし、トーストで通知します（`sendMessage()` 冒頭のゲート）。
- 通常ユーザーはページ読込時の自動解決でトークンがキャッシュされるため、追加の待ち時間や表示は発生しません。

### 2. Turnstile 不合格時もスコアを送信（失敗をペナルティ化）

- クライアント側のテレメトリ送信で、怪しい挙動を検出してトークンが取れなかった場合は、従来のように報告を中止せず `turnstile_failed: true` を付けて報告を送ります（`chat_core.v4.8.700.js`）。
- サーバー側の `/api/bot-telemetry` は `turnstile_failed` 付きの報告を拒否せず、挙動スコアにペナルティ +2 を加算して評価します（`app.py`）。
- トークンなし・フラグなしの報告は従来どおり `403 turnstile_failed` で拒否（未改変クライアントからの偽報告を防止）。

### 補足

- 送信ブロックは UI レベルのゲートです。`appearance: 'interaction-only'`（V4.8.699）により通常は認証ボックスは表示されず、Cloudflare が人確認を必要とする場合だけボックスが表示されます。
- 正常な人間は Turnstile が自動解決されるためブロック・ペナルティ対象になりません。Turnstile スクリプトを遮断する環境（強力な広告ブロッカー等）では送信がブロックされ、繰り返すとスコアが蓄積して BAN される可能性があります。
