# V4.8.571 (2026-06-02)

## ログイン時の Turnstile 優先順位問題の修正

### 問題
- パスワードを間違えて入力した状態で Turnstile（Cloudflare認証）の完了前にログインボタンを押すと、「ユーザー名またはパスワードが正しくありません」という具体的なエラーが表示されてしまっていた。
- これにより、Turnstile を突破していなくてもユーザー名の存在やパスワードの正誤に関する情報が漏洩する可能性があった（情報漏洩 / プライバシー上の問題）。

### 原因
- クライアント側で Turnstile の完了を待たずにフォーム送信ができてしまい、サーバー側のチェックが通った場合に credential エラーが先に返されていた。
- サーバー側は Turnstile チェックを credential チェックの前に置いていたが、クライアント側で早期ブロックができていなかったため、UX 上で「パスワードエラーが優先して見える」状態になっていた。

### 修正内容
- **クライアント側 (`app/templates/login.html`)**:
  - Turnstile ウィジェットに `data-callback` / `data-expired-callback` / `data-error-callback` を追加し、完了状態を追跡。
  - 通常ログイン送信時とパスキーログイン送信時の両方で、Turnstile トークンが存在しない場合は即座に「認証を完了してください」を表示して送信をブロック。
  - これにより、Turnstile が完了していない限り、サーバーまで credential 情報が送られず、具体的なパスワードエラーメッセージが返ることはなくなった。
- サーバー側の Turnstile 優先チェック（既存）はそのまま維持（二重防御）。

### 影響
- Turnstile 必須のログイン画面で、認証が完了するまで credential エラーが一切返らなくなった（セキュリティ・プライバシー向上）。
- 通常の「正しい Turnstile 完了 → 誤ったパスワード」ケースでは、従来通り「ユーザー名またはパスワードが正しくありません」が表示される。
- その他のページ・機能への影響なし。
