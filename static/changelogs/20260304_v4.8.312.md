# V4.8.312 (2026-03-04)

## 変更概要
- 初回表示遅延デバッグのため、TTFT計測を `content` のみから `status / thought / content` の3系統に拡張。
- サーバー内フェーズ計測（route/dispatch/worker/provider/stream）を追加し、Redis経由で時刻を収集してDBへ永続化。
- 条件を満たす初回送信で、RQキューを経由しない高速経路（direct実行）を追加。
- 添付なし時に不要な添付前処理をスキップして、送信前処理のオーバーヘッドを削減。

## 詳細
- フロントエンド (`templates/chat_app.js`)
  - 送信開始から初回 `status` / `thought` / `content` までのレイテンシをそれぞれ `POST /api/metrics/first_token` へ送信。
- バックエンド (`app.py`)
  - `chat_latency_trace` テーブルを追加（job単位で分解タイムラインを保存）。
  - `/chat_stream` にて以下を実装:
    - フェーズ時刻の記録（route受信・dispatch・stream open・client配信初回など）。
    - 新規チャット1通目かつ軽量条件時の direct 実行（キュー迂回）。
  - `background_chat_task` にて以下を実装:
    - worker開始、providerリクエスト開始、provider初回chunk/status/thought/content時刻の記録。
    - 添付なし時の前処理短縮。
  - `/api/metrics/first_token` を拡張:
    - event種別別24h集計（status/thought/content）
    - `chat_latency_trace` へのupsert
    - フェーズ分解ログの出力

## 期待効果
- 「どこで遅いか」を毎回分解して把握可能。
- 軽量な初回送信でTTFT短縮（キュー待ちの上乗せを回避）。
