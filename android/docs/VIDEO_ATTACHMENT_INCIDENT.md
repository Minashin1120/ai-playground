# 動画を添付した送信で回答が止まる問題（2026年10月）

2026年10月6日までに、動画を添付して Gemini のモデルへ送信したときに回答が止まる・失敗する問題を、3つ修正しました。症状は似ていますが、原因と起きる条件はそれぞれ異なります。

| | 症状 | 起きる条件 | 影響した版 | 修正した版 |
|---|---|---|---|---|
| 1 | 回答が終わらず処理中のまま止まる。その後、チャットを開けない・停止できない・削除できない、同期が「同期中…」のまま進まない | Android版のサーバー不使用モードで、Geminiに動画などの大きなファイルを添付する | Android 1.41.31以前 | Android 1.41.32、1.41.34 |
| 2 | 「動画(…)のアップロードに失敗しました」というエラーで回答が失敗する | Web版、またはAndroid版の通常（サーバー経由）で、Geminiに動画または20MBを超えるファイルを添付する | Web V4.8.1058以前 | Web V4.8.1059 |
| 3 | 送信の直後に回答が止まったように見える | Android版の通常（サーバー経由）で、回答の生成中にアプリを離れる（ホームに戻る、別のアプリに切り替える、画面が消えるなど） | Android 1.41.35以前 | Android 1.41.36 |

どの問題も、プロンプトキャッシュの設定とは関係ありません。

## 利用者の対応

- Android版は 1.41.36 以降へ更新してください。
- Web版は、サーバーの更新で修正済みです。利用者の操作は必要ありません。
- 問題1で止まったままのチャットがある場合も、更新後は、ほかの操作を待たせずに同期を進めます。更新しても「同期中…」から進まない場合は、設定「一般」タブの「接続」カードで未送信の件数を確認し、「今すぐ同期」を押してください。

## 問題1: サーバー不使用モードで回答と同期が止まる

サーバー不使用モードでは、端末から AI の各社へ直接送信し、送信前の添付ファイルとサーバーへ保存する前の回答を端末に暗号化して保存します（[接続モード](CONNECTION_MODES.md)）。数十MBの動画では、次の4つが重なっていました。

1. **動画を送信内容に直接埋め込んでいた。** Gemini へ送るとき、動画をBase64で文字列にして送信内容（JSON）に含めていました。Base64にすると元の約1.33倍の大きさになり、元のデータと合わせてメモリーを大きく使います。
2. **暗号化したファイルの読み込みが非常に遅かった。** 端末に保存するファイルは、ファイル全体を Android Keystore の鍵で直接暗号化していました。Keystore はデータを少しずつ受け渡すため、数十MBでは読み込みに長い時間がかかり、復号が終わるまで全体をメモリーに抱えていました。
3. **ファイルの読み書き中に、ほかの操作が待たされていた。** 端末の保存領域は1つのロックで守られており、大きなファイルを読み書きしている間、チャットを開く・削除する・同期するといった操作が終わるまで進めませんでした。
4. **同期が重なって始まっていた。** 中断した同期がファイルの読み込みを終える前に次の同期が始まり、同じ動画を何度も並行して読み込んでいました。調査では、アプリが使えるメモリー 256MB のうち 243MB まで使っていたことを確認しています。

その結果、回答が終わらないまま処理中になり、アプリを強制終了した後も、チャットを開けない・停止できない・削除できない、同期が進まない状態になりました。アプリのデータを消去すると、端末に残っていた未送信の動画も消えるため、元に戻っていました。

### 修正

- **1.41.32:** 動画と20MBを超えるファイルは、Gemini の Files API へアップロードしてから、その参照を送信するようにしました。アップロード後、Gemini での処理が終わるまで（最大2分）待ちます。Vertex AI では、これまでどおり送信内容に含めます。ファイルの読み書きを、ロックの外で行うようにしました。
- **1.41.34:** 端末に保存するファイルの暗号化を、ファイルごとに作る鍵で 1MB ずつ区切って暗号化する方式に変えました。ファイルごとの鍵は Android Keystore の鍵で暗号化して保存するため、Keystore で扱うのは小さな鍵だけになり、大きなファイルも速く読み書きできます。以前の方式で保存したファイルも、そのまま読み込めます。あわせて、前の同期が終わるまで次の同期を始めないようにしました。停止ボタンを押すと、1MB の区切りごとに添付ファイルの読み込みも中断します。

## 問題2: サーバー経由で Gemini へ動画を送るとエラーになる

サーバーは、動画と20MBを超えるファイルを Gemini の Files API へアップロードしてから送信します。このアップロードの設定で、同じ項目を2通りの名前（`display_name` と `displayName` など）で同時に渡していました。サーバーが使っている Google Gen AI SDK は、決められていない項目を受け付けないため、アップロードが毎回失敗し、次のようなエラーが回答に表示されていました。

```
動画(…)のアップロードに失敗しました: 1 validation error for UploadFileConfig
display_name
  Extra inputs are not permitted [type=extra_forbidden, …]
```

Web版とAndroid版の通常（サーバー経由）のどちらでも起きていました。サーバー不使用モードは端末から Gemini へ直接アップロードするため、このエラーは起きません。

### 修正

- **V4.8.1059:** アップロードの設定を、SDK が受け付ける名前（`mime_type` と `display_name`）だけで渡すようにしました。設定が SDK に受け付けられることを確かめるテストを加えました。

## 問題3: アプリを離れると回答の受信が止まる

Android版の通常（サーバー経由）では、回答の生成中にアプリが画面から離れると、回答の受信を止めていました。回答はサーバーで生成が続き、アカウントにも保存されていましたが、アプリの画面では送信の直後に止まったように見えていました。アプリに戻ると履歴を読み込み直し、生成中の回答へつなぎ直していました。Web版は、タブを切り替えても受信を続けます。

### 修正

- **1.41.36:** アプリを離れても回答の受信を続けるようにしました。Android は、しばらく画面から離れたアプリの通信を、切断を知らせずに止めることがあります。そのため、30秒以上離れてから戻ったときは、サーバーで生成中の回答へ自動でつなぎ直します。サーバーがまだ受け付けていない送信は、止めずに送り直しを続けます。

## 調査の方法

原因を特定するため、Android 1.41.33 で管理者アカウントだけの診断ログを加えました。処理の段階と所要時間、メモリーの使用量、処理が止まったときのスレッドの状態を記録し、入力した本文やファイルの中身は記録しません。内容は [Android版の診断ログ](DIAGNOSTICS.md) にまとめています。
