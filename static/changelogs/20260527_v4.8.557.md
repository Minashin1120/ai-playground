# Update V4.8.557 (2026-05-27)

### xAI Grok TTS の本格的な単独モデル化（UI + Backend 完全実装）

xAI のスタンドアロン音声機能の「単独モデル化」を、現在実装可能な範囲で最大限まで推し進めました。

#### 背景
これまで xAI 音声系は主に **Realtime Voice Agent**（双方向会話用、`grok-voice-*` 系）のみがモデル選択リストに存在していました。一方、xAI公式は独立した高品質な **Text-to-Speech (TTS)** API (`/v1/tts`) を提供しており、他のプロバイダー（OpenAI TTS、Gemini TTS、Google Cloud TTS）のように「読み上げ専用モデル」として選択できる状態ではありませんでした。

#### 実施した単独モデル化の内容

**1. モデル追加とUI整備**
- `Audio (TTS)` カテゴリに `grok-tts` を新規追加
- モデル選択時に自動で xAI 専用音声選択UIが表示されるよう拡張：
  - 音声：Eve（デフォルト）、Ara、Rex、Sal、Leo（公式ドキュメント準拠）
- 速度調整（0.7〜1.5倍）、言語指定（BCP-47対応）も利用可能に
- `setup.html` の既定モデル選択肢にも `grok-tts` を追加

**2. バックエンド実装（app.py）**
- TTS Branch に xAI 専用処理を新規追加（`grok-tts` / `xai-tts` 判定）
- ユーザーの `xai_api_key`（または管理者フォールバック）を使用して `POST https://api.x.ai/v1/tts` を直接呼び出し
- 対応パラメータ：
  - `voice_id`（UIで選択した音声）
  - `language`
  - `speed`
- 生成された音声ファイルは既存のTTSフローと完全に統合：
  - ファイル保存 → E2EE暗号化対応 → チャット内 `<audio>` タグ表示 → 生成履歴管理
- 既存の OpenAI / Gemini / Google TTS の処理を一切壊さないよう条件分岐で安全に実装

#### 現在の対応状況

| 機能               | ステータス          | 備考 |
|--------------------|---------------------|------|
| Realtime Voice Agent | 対応済み（V4.8.555で `grok-voice-latest` 追加） | 双方向会話用 |
| Grok TTS (単独)    | **本実装完了**      | 読み上げ専用として利用可能 |
| Grok STT (単独)    | モデルエントリレベル | 完全なUI/処理フローは今後 |

STTについては、用途が「音声ファイルの文字起こし」であるため、既存のファイルアップロード機能との統合方法を慎重に検討する必要があり、今回はTTSを優先して最大限実装しました。
