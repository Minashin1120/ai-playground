# V4.8.701 (2026-08-03)

## Turnstile 検証を API レベルでも強制（送信ゲートをサーバー側へ拡張）

前版（V4.8.700）は Turnstile チェック中の操作ブロックを UI レベルで実装していましたが、UI を経由せず API を直接呼ぶクライアントはブロックを回避できていました。本版ではサーバー側（`app.py`）にも Turnstile 未検証を弾く API レベルのゲートを追加し、UI と API の両方で一貫してブロックします。

### 1. サーバー側の検証状態（Redis マーカー）

- 新しいエンドポイント `/api/bot/turnstile-verify`（`POST`・要ログイン）を追加。クライアントが取得した Turnstile トークンを `verify_turnstile()` で検証し、成功すると Redis へ `bot:tst:v:{user_id}`（TTL 15分）を保存します。失敗時は `403 turnstile_failed`、BAN 済みは `403 banned`、30回/分のレート制限付き。
- 検証状態は Redis に保存するため、DB 変更はありません。

### 2. チャット送信系 API へのゲート適用

- 以下の送信系エンドポイントで、ボット検出が有効な非管理者ユーザー（`globalEnabled` かつ `accountEnabled` かつ非管理者かつ Turnstile キー設定済み）に対し、送信前に `_bot_turnstile_gate()` を実行します。
  - `/chat_stream`（通常送信）
  - `/chat_stream_resume`（再接続・復帰）
  - `/api/browser_fast_mode/save`（ブラウザ高速モード保存）
- ゲート判定は「① Redis の検証マーカーあり → 許可（高速パス）」「② リクエスト本文の `turnstile_token` が検証成功 → 許可＋マーカー更新」「③ どちらも不可 → `403 {error: 'turnstile_required'}`」の順です。通常ユーザーはページ読込時の自動解決でマーカーが立つため待ち・表示は発生しません。マーカーなし・トークンなしの直接 API 呼び出しだけがブロックされます。
- 管理者・ボット検出無効・Turnstile 未設定の環境ではゲートは動作しません（従来どおり）。

### 3. クライアント側の変更（`chat_core.v4.8.701.js`）

- `verifyTurnstileOnServer()` を追加し、Turnstile トークン取得成功時（ページ読込時の自動解決コールバック・再実行時）に `/api/bot/turnstile-verify` へ送信してマーカーを確立します（60秒間の送信重複を抑制）。
- `sendMessage()` のゲートで取得したトークンを `/chat_stream` のリクエスト本文（`turnstile_token`）へ含めます。ブラウザ高速モード保存・`/chat_stream_resume` にもトークンを付与し、マーカー失効時でもサーバー側インライン検証で継続できます。
- 送信時に `403 turnstile_required` を受けた場合は再検証を試み、「もう一度送信してください」と案内します（入力は保持されるため再送信のみで続行可能）。

### 補足

- UI レベルのゲート（トークンが全く取れない場合は送信自体をブロック）は V4.8.700 から維持しています。API レベルではそれに加えて「未検証状態での直接 API 呼び出し」をブロックするため、UI を介さないボットからの送信・保存が遮断されます。
- 人間の通常利用では Turnstile が自動解決されマーカーが立つため、ブロックや待ち時間は発生しません。
