# V4.8.712 (2026-08-03)

## コンソール合成イベントの即BAN＋ロックのIP/クッキー記録（cookie削除バイパス対策）

ユーザー指摘に基づき、以下の2点を対応しました。

### 1. コンソール等からの合成イベント（DOM叩き）を即BAN（`chat_core.v4.8.712.js` / `app.py`）

- コンソールや自動化スクリプトが `dispatchEvent(new PointerEvent('pointerdown'))` などで発火させるイベントは **`isTrusted === false`** になります（通常の人間操作は `true`）。これをボット検知で検出します。
- クライアント `botTelemetry` の `recordClick` / `recordKey` が `isTrusted === false` を検出すると、`untrustedInput` フラグを立てて即座に報告（`untrusted_input: true` をペイロードに付与）。
- サーバー `/api/bot-telemetry` は `untrusted_input` を受けると、Turnstile状態に関係なく**即 `_apply_bot_ban("Synthetic (script-injected) input events detected")`** でBANします。従来の「挙動スコア8/6が必要」を待たず、合成イベントは決定的なボット根拠として扱います。
- これにより、検証手順書の `rapidClicks` / `banByClicks` などのコンソールコマンド実行 → **即BAN** されます。

### 2. ロックのIP/クッキー記録（cookie削除→新規アカウント作成のバイパス防止）（`app.py`）

- 連打ロック適用時（`_apply_bot_lock`）に、ユーザーIDキー `bot:lock:{user_id}` に加えて **`bot:lock:ip:{ip}` / `bot:lock:cookie:{token}`** にもロックを記録（TTL 10分、理由も保存）。
- `_bot_lock_gate` / `_bot_lock_info` は、現在のユーザーIDロックに加えて**現在のIP/クッキーに紐づくロック**も判定。cookieを消して新規アカウントを作成しても、**同一IPからならロックが適用**され、バイパスできません。
- ロックの繰り返し（3回）でBANになる仕組みも、IP/クッキーロック経由のアクセスでも機能します。
