# Web版との機能・デザイン一致ロードマップ

## Android 1.13.21：オフライン閲覧と端末キャッシュ管理

- 表示済みの履歴・添付ファイルをAndroid Keystoreで暗号化し、`noBackupFilesDir`へ保存してネットワーク切断時も閲覧できるようにしました。
- 設定から「表示済み部分のみ／全件同期」と「Wi‑Fiのみ／モバイルデータ通信も許可」を選択できます。初期値は表示済み部分のみ、Wi‑Fiのみです。
- 設定からチャット履歴とファイルのキャッシュをカテゴリ単位で削除できます。ログアウト時はキャッシュを保持し、同じアカウントの再連携後に再利用します。
- 自動同期・手動同期・キャンセル、オフライン時の通信依存操作の無効化を追加しました。未取得の古い履歴と未表示ファイルはオンライン復帰後に取得します。

## Android 1.13.13：Web UI配置と操作感の追加同期

Web版V4.8.1001の画面構造を基準に、ネイティブComposeの主要導線を更新しました。

- 履歴サイドバー／DrawerにPDF共有、ヘルプ、更新履歴を追加し、Androidの戻る操作でモーダル・Drawerを順に閉じるようにしました。
- スマートフォン、横画面、タブレットをレイアウトクラスで判定し、タブレット2ペインとスマートフォンDrawerを維持します。
- Composerのモデル選択、リッチ貼り付け、画像マスク、音声入力をWebの入力シェル内の配置へ寄せ、送信キーに応じたプレースホルダーを表示します。
- 会話の「一番下へ」操作と、スマートフォン向け全画面モーダル枠を追加しました。
- GitHub Actionsでの検証対象を追加しましたが、実機の寸法、TalkBack、IME、縦横回転、音声品質は未確認です。

## Android 1.13.0 以降：設定項目とスラッシュコマンドの同期

Webの設定モーダルと同じ分類（一般／APIキー／プロンプト／表示／データ／アカウント／セキュリティ／2要素認証／フィードバック／MCP）をネイティブ設定へ載せました。検索、システムプロンプト、Vision Model、前回設定の継続、プロンプトバー表示、STT既定、テーマプリセット、Liquid Glass、ストレージ使用量、フィードバック送信、MCPの有効切替、スラッシュコマンド、一時チャット／Compressチップ、Gemini Native Audio セッションを追加しています。

APIキー・パスワード・2FA登録・MCP OAuth秘密・アカウントZIP・管理者機能は引き続き認証済みWeb導線です。Gemini 3.1 Live / 3.5 Live Translate / Live Transcribe は、サーバー中継のRealtimeセッションを通じてAndroidネイティブ音声に対応します。

## Android 1.12.0：ネイティブUIを維持した追加同期

利用者の指定により、引き続きネイティブUIでWeb版の主要導線を同期します。

- URL／Maps／File／SysPromptと、設定画面の既定値（Python／MCP、Thinking level／budget、Reasoning effort、Safety、テーマ色）をBearer API経由で同期します。
- Canvasは履歴コードを編集して入力欄へ反映、Codingは履歴コードを対象選択して候補・ソースを送信します。
- GPT-Imageマスクの端末描画・PNGアップロードと、クリップボードHTMLの安全なテキスト化によるリッチ貼り付けを追加しました。
- OpenAI／Grok Realtimeは端末マイク・SSE音声再生・発話確定・保存、LyriaはSSE再生・一時停止／再開・保存までネイティブ対応します。APIキーは端末へ渡しません。
- Gemini動画の長さ・アスペクト比・解像度（4Kは対応モデルのみ）をモデル別に表示・送信します。

未完了：管理者専用のHTML→PDFリッチ貼り付けと秘密設定、実機での全画面寸法比較です。Gemini Liveはサーバー中継のネイティブセッションを追加しましたが、長時間接続・端末ごとの音声品質は実機確認が必要です。

## Android 1.11.0：ネイティブUIを維持した追加同期

利用者の指定によりネイティブUIを維持します。WebViewへの置き換えは行いません。

- Webのモデル定義111件から正式表示名・説明・価格・カテゴリ・タグ・追加順を生成し、モデル一覧と開始画面に反映。APIが許可しないモデルは有効化しません。同期は `node android/ci/sync-web-catalog.mjs`、差分確認は同コマンドの `--check` で行います。
- 既存APIで扱えるThinking level／budget、reasoning effort、File／SysPrompt／URLs、安全性設定、GPT／Gemini／Grok画像設定、Grok動画、OCR、TTS、xAI詳細設定を入力欄へ追加。設定はモデルごとに保持し、範囲外の数値は送信前に拒否します。
- マイクからAndroidの音声認識画面を呼び出して入力欄へ反映。対応アプリがない場合は説明を表示。Web側の録音・モデル選択式の文字起こしとは異なります。
- 設定・Gems・ライブラリ・Batch・チャット設定に共通モーダル枠を適用。一般設定を分類し、ライブラリに画像プレビューとファイルを開く操作を追加。

（1.12.0でCanvas／Coding、マスク、リッチ貼り付け、Realtime／Lyria、Gemini動画詳細、既定値同期を追加しました。）

## 1. この文書の目的

公式Androidクライアントを、Web版と同じアカウント・データ・主要機能・視覚的なブランドを持つネイティブアプリへ発展させるための継続資料です。新しい作業セッションで「AndroidクライアントをWeb版と同じ機能、デザインにして」と依頼された場合は、本書を進捗の正本として使い、差分調査だけで作業を終えず、未完了項目の実装・検証・配布まで進めます。

通信・認証・署名・サーバー設定の正本は [`../deploy/ANDROID_CLIENT.md`](../deploy/ANDROID_CLIENT.md)、Web／Android同期の作業規則は `~/docs/android_sync.md` です。本書は機能とデザインの到達目標、現在地、実装順を管理します。

## 2. 目標の解釈

「同じ」はWebのHTMLをそのまま表示する意味ではありません。チャット、履歴、設定、モデル固有機能などの結果と主要な操作を一致させ、Web版の色、階層、用語、状態表示、情報量をAndroidの操作体系へ置き換えます。

- 主画面をWebViewで包まず、Kotlin／Jetpack ComposeのネイティブUIを維持する。
- ログイン、2FA、端末連携承認など、Webで安全に完了させる設計済みの認証フローはCustom Tabsを使ってよい。
- Androidの戻る操作、共有シート、Photo Picker、通知、アクセシビリティ、画面サイズへの適応は、Webと見た目を完全複製するよりプラットフォーム標準を優先する。
- APIキー、Cookie、サーバー秘密情報をAndroidへ渡して機能を再現しない。必要な機能は権限を限定したネイティブAPIとして設計する。
- Androidで合理的に提供できない管理者専用・ブラウザー専用機能は、理由と安全なWeb導線を本書に記録する。未実装のまま黙って省略しない。

## 3. 完了条件

機能・デザイン一致は、次の条件をすべて満たした状態です。

1. Web版の利用者向け機能を棚卸しし、本書の各項目が「完了」「Web導線として完了」「対象外（理由記載）」のいずれかになっている。
2. 同じアカウント、スレッド、メッセージ、添付、モデル設定について、WebとAndroidのどちらで変更しても他方で矛盾なく確認できる。
3. 通常チャットだけでなく、対象モデルの入力設定、生成結果、エラー、停止、再接続、履歴表示が一致する。
4. Web版のデザイントークンと主要画面の構造をComposeに定義し、ライト／ダーク、文字拡大、縦横画面、スマートフォン／タブレットで破綻しない。
5. ローディング、空状態、オフライン、期限切れ、BAN、Turnstile、メンテナンス、レート制限を誤解のない文言で表示する。
6. TalkBack、タップ領域、コントラスト、フォーカス、選択可能テキスト、システムの「戻る」を確認する。
7. Android単体テスト、API回帰テスト、lint、debug／release APK、固定署名照合、主要フローの実機確認を完了する。
8. `version.properties`、本書、`README.md`、`../deploy/ANDROID_CLIENT.md`、GitHub Releaseの内容が実装と一致する。

## 4. 現在の基準

配布済み基準版はAndroid 1.13.13、Web V4.8.1001です。主要機能のネイティブ実装と、安全上ブラウザーで扱う機能への明示的なWeb導線まで完了しています。Android CIでは単体テスト、lint、debug／release APK、固定署名を検証済みで、実機確認が必要な項目は下表に残しています。

状態の意味：

- **完了**：基本フローをネイティブ実装し、自動テストまたはActionsで検証済み。
- **一部**：基本機能はあるが、Web固有の操作、表示、設定の一部がない。
- **未実装**：Androidに相当機能がない。
- **Web導線**：Android内で完結せず、認証済みブラウザーへ案内する。

## 7. 推奨実装順

### Phase 1：チャット体験とデザイン基盤（Android 1.1.2で完了）

1. Webの色・寸法・タイポグラフィをComposeのDesignSystemへ集約する。
2. 安全なMarkdown、コード、リンク、引用、数式、添付プレビューを実装する。
3. モデルメタデータとモデル別設定をAPI化し、選択画面とComposerを一致させる。
4. メッセージ操作、エラー、空状態、進捗、オフライン復帰を整える。
5. スマートフォンとタブレットのナビゲーションを分ける。

### Phase 2：履歴・添付・設定（Android 1.7.0で完了）

1. スレッド設定、ブックマーク、一時チャット、分岐、PDF出力を実装する。
2. アップロード進捗、キャンセル、プレビュー、カメラ、チャンクアップロードを実装する。
3. ファイルライブラリ、Gems、一般設定、セッション管理を実装する。
4. Webでのみ扱う秘密情報や高度なセキュリティ設定には、明確なWeb導線を用意する。

### Phase 3：高度な生成機能（Android 1.8.0で完了）

1. Batchと完了通知はネイティブ実装済み。
2. 画像、動画、OCR、TTS、文字起こしは共通ストリーム契約で実装済み。Gemini動画詳細とGPT-Imageマスクもネイティブ化。
3. MCP、Coding、Python結果は構造化表示済み。Coding履歴対象とCanvasソース編集を追加し、秘密設定と実ファイル同期はWeb導線。
4. OpenAI／Grok／Gemini Realtime音声とLyriaをネイティブセッション化。秘密設定と管理者機能はWeb導線。

各Phaseは巨大な一括変更にせず、独立して利用できる単位で版を上げ、Actionsと実機確認を行います。ただし、一つの機能についてサーバーだけ、またはAndroidだけを未整合のまま公開しません。

## 8. 作業セッションごとの進め方

1. 本書と `~/docs/android_sync.md` を読む。
2. 対象機能をWeb側の分割READMEで特定し、関係するファイルだけを読む。
3. 現行APIで安全に実装できるか確認する。設定・秘密情報APIをそのままBearerへ開放しない。
4. 必要ならAndroid専用API、サーバー回帰テスト、Compose UI、Android単体テストを同じ作業で実装する。
5. 対応する本書の行とデザイン差分を更新する。完了していない項目を「完了」にしない。
6. Androidを変更したら `VERSION_CODE` と `VERSION_NAME` を更新する。
7. Web側の通常リリース検証・公開とAndroid Actionsを完了し、固定署名、artifact、GitHub Releaseを確認する。
8. 実機未確認の項目は明記し、確認済みと推測を区別する。

## 9. 検証マトリクス

機能追加ごとに、該当する行をテスト対象へ含めます。

| 観点 | 必須確認 |
|---|---|
| アカウント | 通常、2FA、暗号化設定、失効、期限切れ、BAN、Turnstile |
| 通信 | Wi-Fi切替、タイムアウト、429、503、途中EOF、再接続、二重送信防止 |
| データ | Web作成→Android表示、Android作成→Web表示、削除・編集・添付の相互反映 |
| 表示 | ライト／ダーク、文字拡大、日本語、長文、コード、数式、RTL候補、空状態 |
| 端末 | API 26、最新API、スマートフォン、タブレット、縦横、低メモリ復帰 |
| 安全性 | Cookie混入なし、別originへBearer送信なし、HTTPS限定、バックアップ除外、所有者検証 |
| 配布 | versionCode増加、固定fingerprint、debug/release成功、APK SHA-256、Release資産 |

## 10. 進捗更新ルール

- 機能を実装した版で、この文書の状態と「次の作業」を更新する。
- 新しいWeb機能を追加したら、Android実装の有無にかかわらず機能差分へ追加する。
- APIやUIのファイル配置が変わった場合は `README.md` の地図も更新する。
- 基準版は、検証済みのAndroid ReleaseとWebリリースに合わせて更新する。
- 未実装項目を削除して差分を隠さない。対象外にする場合は理由と代替導線を書く。
- 本書に詳細な通信ペイロードや署名手順を重複させず、`../deploy/ANDROID_CLIENT.md` を更新して参照する。
