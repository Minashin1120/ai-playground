# V4.8.631

## リッチ貼り付けの再現性・安定性を全面改善

- OpenAI公式ドキュメント等の実際のクリップボードHTMLに含まれる、色、背景、罫線、余白、フォント、文字装飾、表、コードブロック、flex/grid等の安全な計算済みスタイルを、プレビューからPDF生成まで維持するようにしました。
- 全選択した大規模ページでは、本文の大部分を占める `main` / `article` を安全に抽出し、サイト全体のナビゲーションを混入させず、ページタイトルと本文構造を残すようにしました。
- ブラウザPDF生成時に貼り付け元の装飾を `!important` で上書きしていたリセットCSSを撤去しました。
- ブラウザ描画をCSS Color 4（`oklab()` / `oklch()` 等）対応の `html2canvas-pro 2.3.2` へ更新し、`jsPDF 2.5.1` とともに同一オリジン配信へ変更しました。CDN障害や読み込み失敗後の再試行不能も解消しています。
- 外部画像によるCanvas汚染でPDF全体が失敗しないようにし、貼り付け画像を遅延読み込みせず変換前に待機するようにしました。
- 1500pxの画像をA4 1ページへ載せて下端が欠けていたページングを、A4比率の高さで全内容を順に分割する方式へ修正しました。

## サーバー側PDF生成

- 要素を限定的に再構築していたReportLab中心の処理から、HTML/CSSを直接組版する `WeasyPrint 69.0` を優先する方式へ変更しました。ReportLabは障害時のフォールバックとして維持しています。
- 大規模な画面用flex/gridを印刷向けに平坦化し、特定サイトで組版が極端に遅くなる問題を解消しました。
- WeasyPrintを制限時間付きの分離プロセスで実行し、取得可能なリソースを検証済みdata画像だけに限定しました。外部URL画像は取得せず、安全な代替表示へ変換します。
- 不正タグ、イベント属性、危険なCSS URL、過大なdata画像、過剰なDOM要素をサーバー側でも再検証します。
- 依存関係監査で検出された既知脆弱性へ対応し、Pillowを12.3.0、Clickを8.3.3、joserfcを1.6.8、soupsieveを2.8.4へ更新しました。

## 検証

- ChromiumでOpenAI公式ドキュメントを実際に全選択・コピーした約36万文字のHTMLを使用し、本文、見出し、6個のコードブロック、現代的な色指定、末尾までの保持を確認しました。
- 同入力でブラウザPDF 8ページ、サーバーPDF 14ページを生成し、ブラウザ側の全ページ生成とサーバー側PDFの目視・全文抽出を確認しました。
- Python/JavaScript構文検査、自己ホスト資産のSHA-384照合、全30件の回帰テストに成功しました。
- `pip-audit` で既知脆弱性が0件であることを確認しました。
