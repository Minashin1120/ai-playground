# V4.8.282 (2026-02-26)

## 停止後の編集送信がフォローアップ扱いになる問題を修正

回答生成を停止した直後、画面上に残っていた楽観描画のメッセージ状態がサーバー実データとずれたままとなり、ユーザーメッセージの編集送信が意図せずフォローアップ扱いになるケースを修正しました。

### 変更内容
* **停止後のスレッド同期を追加**: `templates/chat_app.js` の `sendMessage()` で `AbortError`（停止ボタン含む）発生時に、`loadMessages(..., { preserveDraft: true, silent: true })` を実行してスレッド状態を再同期。
* **再開ストリーム停止時も同期**: `resumePendingStream()` の `AbortError` 時にも同様のサイレント同期を追加し、停止後の `currentParentId` / `allMessages` の不整合を防止。
* **編集系の回帰抑止**: 編集送信中に停止した場合は、同期成功時のみ旧ブランチ復元をスキップし、サーバー側の正しい状態を優先。
* **回答再生成の確認**: `regenerateMessage()` は既存の編集送信フロー経由で動作しており、今回の停止後同期により同系統の状態ズレ影響を受けにくくなることを確認。
* **表示バージョン更新**: `chat.html` の表示バージョンと `chat_app.js` キャッシュバスターを `V4.8.282` に更新。
