# Android版の診断ログ

AI Playground のAndroid版（1.41.33以降）は、サーバーの**管理者アカウント**でログインしているときだけ、不具合の調査に使う診断ログを記録し、ログインしているサーバーへ送ります。管理者以外はこの自動送信の対象外です。別途、端末の操作ログとアカウントごとのサーバー調査ログは、それぞれの設定がオンの場合だけ記録します（後述）。

診断ログは、送信・回答・同期・チャットの読み込みが止まったり失敗したりしたときに、どの段階で何が起きたかを確かめるためのものです。通常（サーバー経由）とサーバー不使用モードのどちらでも記録します。

## 記録する内容

| 種類 | 内容 |
|---|---|
| 処理の段階 | 送信の開始・終了・停止・失敗、回答の生成の各段階、添付ファイルの保存と読み込み、同期、チャットを開く・再読み込みする・削除する操作、アプリの起動、アプリが画面に出た・離れたこと |
| 数値 | 所要時間、ファイルのサイズ、件数、入力した本文の文字数、アプリが使っているメモリーの量 |
| 種類・状態 | モデル名、添付ファイルのMIMEタイプ（`video/mp4` など）、通信先の種類（Gemini、Vertex AIなど）、AIの各社でのファイルの処理状態、プロンプトキャッシュなどの設定のオン・オフ |
| 識別子 | 検証済みの内部ID、操作のランダムID、アプリのプロセス番号 |
| 結果 | 固定のイベント種別、HTTP状態、成功・失敗・中断。進み具合やエラーの文言そのものは記録しません |
| 例外 | 許可した例外の種類とアプリ内のファイル・行位置（最大24段）。例外メッセージは記録しません |
| 停滞時のスタック | 送信・回答・同期・読み込みが20秒以上進まないとき、アプリコードのファイル・行位置（最大24段）。60秒に1回までです |

Web・Android・サーバーで共通の許可項目・型・固定値だけを保存します。未知の項目や自由文、任意の入れ子データは捨てます。翻訳、画像分割、HTMLプレビュー、音声再生、更新ダウンロード・インストール、生成・同期などの開始・結果も対象です。

サーバーとの通信では、接続の準備が終わって要求ヘッダーを送る時点を、操作ログの `http`（`phase: start`）に記録します。`ms` は通信を登録してからその時点までの待ち時間です。応答ヘッダーの受信は従来の `http`（`phase: done`）、途中の送受信の失敗は `http.read_error`、最終的な失敗や中断は `http.error`／`http.cancel` で確認できます。再利用した接続の切断から自動回復する場合も途中の失敗を記録します。処理時間と例外の種類、許可された経路だけを残し、例外の文言や画像の参照は記録しません。

Android 1.70.43以降は、同じサーバー通信の `http` と失敗・中断のイベントに端末で作ったランダムな `parent_op` を付けます。要求本文の送信開始・終了は `type: start` の `phase: start`／`done`、応答の読み取り終了は `type: done` の `phase: done` です。送信終了の `bytes` は送信バイト数です。応答ヘッダーにサーバーの診断IDがあれば、従来どおり `op` に記録します。

端末からAI事業者へ直接送る通信は、操作ログの `direct` にランダムな通信ID `op` と、開始からの経過時間 `ms` を記録します。`type` が `accepted` は通信開始、`start` の `phase: start`／`done` は要求本文の送信開始／終了、`status` は応答ヘッダー受信、`message` は最初のストリームイベント、`done` は受信処理の終了です。送信終了時には `bytes` も記録します。失敗・中断は同じ `op` の `direct.error`／`direct.read_error`／`direct.cancel` に記録します。ストリームイベントの内容、本文、添付、ファイル名、キーは記録しません。事業者側の処理時間を端末から直接測ることはできず、送信終了から応答までの時間にはネットワーク待ちも含まれます。

同期後に端末内の添付が整理された場合、開いたままのプレビューがサーバー側の画像へ取得先を切り替える段階を `store.file_read`（`ok: false`、`retry: true`）に記録します。端末内のファイルが無く、切り替え先も無い場合は `retry: false` です。参照やファイル名は記録しません。最終結果は画像ビューアーの読み込み結果で確認できます。

Android 1.70.49以降は、送信の開始・受信イベント・完了・失敗・中断と、生成済みジョブへの再接続に、回答ごとに作ったランダムID `op` を付けます。複数のチャットで同時に生成している場合も、回答ごとの経過を区別できます。IDは本文・タイトル・添付から作らず、収集条件と保存・送信の扱いは従来どおりです。

## 記録しない内容

- 入力した本文、回答の本文、思考の内容
- 添付ファイルの中身（画像・動画・文書のデータ）
- チャットのタイトル、添付のファイル名、URI、自由入力のURL
- 例外・通知・プロバイダ応答の文言
- APIキー、パスワード、ログイン情報

## 端末での保存

- 記録は、送れるまで端末のアプリ専用の領域（`noBackupFilesDir/diagnostics/pending.jsonl`）に置きます。アプリを強制終了しても、次に起動したときに送れるようにするためです。この領域は端末のバックアップに含まれません。
- 768KBを超えたときは、古い方の半分を削除します。
- サーバーが受け取った分は、端末から削除します。

## 送信

- アプリが動いている間、10秒ごとに、ログインしているサーバーの `POST /api/mobile/v1/diagnostics` へ送ります。1回に送るのは200件・約60万文字までです。オフラインのときは送りません。
- 通信は、ほかのAPIと同じログイン情報（Bearerトークン）を使い、https で送ります。
- サーバーが管理者ではないと応答した場合（403）、アプリは記録を止め、端末に残っていた記録を削除します。

## サーバーでの保存

- サーバーは管理者以外からの送信を拒否します（403）。1回の送信は1MB・500件まで、1分に60回までです。
- 受け取った1件を1行のJSONとして、アプリのディレクトリの `diagnostics/android-diagnostics.log` に追記します。行には、受信時刻、アカウントのID、ログインセッションのID、アプリの User-Agent（80文字まで）が加わります。
- 1行が256KBを超える記録は、イベント名と大きさだけに置き換えます。
- ファイルが20MBを超えると `diagnostics/android-diagnostics.log.1` へ移し（前の `.1` は上書きされます）、新しいファイルへ書き始めます。それ以外に自動で削除はしません。
- このファイルはGitの管理対象外です。

## 記録を止める・消す

- 診断ログは管理者アカウントだけが対象で、アプリにオン・オフの設定はありません。アカウントの管理者権限を外すと、アプリは次の送信で記録を止め、端末の記録を削除します。
- アプリのデータを消去すると、端末に残っていた記録も消えます。
- サーバーに保存された記録は、サーバーの運用者が `diagnostics/android-diagnostics.log` と `.1` を削除して消します。

## ログの収集を強化との関係

設定のフィードバックタブの「操作ログを記録する」は端末別のオプトインです。管理者かどうかに関係なく、上記と同じ機密除外を適用した処理段階・通信結果・数値・固定状態を操作ログへ記録します。タップ位置、選択ハンドルなどの既知のウィンドウ種別と座標・大きさ、画面の状態も対象ですが、共有された文字・タイトル・ファイル名、エラー文言は記録しません。

テキスト選択と数式の操作は、操作ログがオンのときだけ `ui.interaction` に記録します。画面部品ごとのランダムIDと操作ごとのランダムIDで、押下・終了・中断、フォーカスとウィンドウの状態、画面内での位置・押した位置・表示範囲からの切れ、選択変更回数、選択メニューの要求・生成・表示可否・非表示・終了、400ミリ秒後の結果を関連付けます。`action_mode_active` はAndroidの選択メニュー管理オブジェクトが存在するかを表し、実際の表示は同時に記録する既知のウィンドウ種別・座標・大きさと照合できます。部品の位置・寸法は画面ルート基準のピクセル、押した位置は部品内のピクセルで、`dpr` からdpへ換算できます。数式では描画の読み込み・完了・失敗、表示範囲と本来の横幅、縮小率、横スクロール位置・上限・開始・終了も記録します。スクロールやメニュー位置調整の毎フレームの記録は行いません。メニュー要求は回数に集約し、表示できない状態の繰り返しは1秒に1回まで記録します。本文・選択した文字・数式・それらから作ったハッシュは記録しません。これらの操作ログを管理者診断へ自動送信することはありません。

操作ログは `noBackupFilesDir/activity_log/` に保存し、設定した保存時間を過ぎたものを30秒ごとの処理と起動・読み出し時に削除します。強制停止中は次回起動時に送信より先に削除します。スイッチをオフにするか「ログを削除」を押すと端末の操作ログを削除します。管理者の自動診断ログは既存の運用ログなので、この保存期間による削除の対象外です。

フィードバック・返信でログ添付を選んだ場合だけ、保存期間内の操作ログをサーバーへ送信します。新規フィードバックの「ログを一緒に送信する」は初期状態ではオフです。送信済みコピーは `feedback/<ID>/logs/` に調査用として保持し、保存期間による自動削除は適用しません。

「サーバー調査ログを記録する」は別の設定です。既定はオフで、アカウントごとに保存し、同じアカウントのWeb版・Android版で共有します。「保存」で反映します。サーバー経由の操作の段階・結果だけをRedisへ記録し、各記録は設定した保存時間で期限切れになります。設定をオフにすると収集を止め、未送信分も削除します。ログ添付を選んだフィードバック・返信には、その時点で残る本人のサーバー調査ログもコピーします。詳細は [ログの収集と保存](../../deploy/LOGGING.md) を参照してください。

## 自分でサーバーを運用する場合

- 保存先は、アプリのディレクトリの `diagnostics/android-diagnostics.log` です。サーバーを起動しているユーザーが `diagnostics/` を作成し、書き込めるようにしてください。
- 記録には管理者アカウントでの利用状況（チャットのID、時刻、処理段階など）が含まれるため、ファイルの閲覧権限はサーバーの運用者だけにしてください。

操作ログとサーバー調査ログの保存時間は、設定のフィードバックタブでそれぞれ1〜8760時間の整数を指定できます（初期値1時間）。操作ログはこの端末に即時反映し、サーバー調査ログはアカウント共通で「保存」で反映します。短縮時は期間外のログを削除します。延長は削除済みのログを復元せず、既存のサーバーログの期限も延長しません。件数・容量の上限に達した場合は保存時間内でも古いログから削除します。

AndroidのDNS補助は、操作ログがオンのときだけ `dns.fallback` に開始・成功・失敗（`phase`）、ランダムな処理ID、所要時間、取得したアドレスの件数を記録します。補助先ごとの試行にも同じイベントを記録し、`index` の0はCloudflare、1はGoogleです。試行は共通のランダムな処理IDで関連付けます。問い合わせたホスト名、IPアドレス、DNS応答、通知の文言、認証情報は記録しません。収集の同意・保存期限・フィードバックへの添付条件は既存の操作ログと同じで、管理者診断への自動送信は追加しません。

## 1.70.64以降の通信段階ログ

操作ログのスイッチがオンのとき、共通の `http` イベントで通信の段階を記録します。管理者診断への自動送信は増やさず、操作ログの既存の保存時間・容量上限・明示添付の条件に従います。パケット単位・本文の断片・進捗ごとの記録は行いません。

`op` は通信ごとのランダムID、`parent_op` は既存のサーバー通信／直接通信のID（ある場合）です。`from` は1=サーバー、2=AI事業者への直接通信、3=更新確認・APK取得、4=DNS補助のHTTPS通信です。`ms` は通信の開始からの経過時間、`phase` は開始・完了・失敗・中断、`index` は接続試行の累計、`pending_count` はこの共通ログの対象となる未完了通信の数です。接続取得前までの時間には、クライアント内の順番待ちも含まれます。

| `reason_code` | 段階 |
|---|---|
| 100 | 通信全体の開始・完了・失敗 |
| 101 | DNS。完了時の `count` は返ったアドレス数 |
| 102 | TCP接続。開始時の `to` はIPv4=4／IPv6=6、完了時はHTTP/1.1=1／HTTP/2=2／その他=0 |
| 103 | TLS接続 |
| 104 | 接続の取得。`to` は同じHTTP方式のコード。DNSや接続開始を経ずにここへ進んだ場合は接続の再利用 |
| 105 | 要求ヘッダーの送信 |
| 106 | 要求本文の送信。完了時の `bytes` は送信量 |
| 107 | 応答ヘッダーの待機・受信。完了時の `status` はHTTP状態 |
| 108 | 応答本文の受信。完了時の `bytes` は受信量 |
| 109 | 接続の解放 |

通信全体の失敗時の `to` は最後に観測した段階です。並行接続試行中は最後の通知で更新されるため、個々のアドレスの失敗箇所を断定する値ではありません。`error_code` は1=名前解決、2=接続拒否等、3=TLS、4=ソケットタイムアウト、5=ソケット障害、6=入出力の中断／全体期限、7=その他の入出力障害、0=未分類です。原因例外も最大16段まで種別だけを調べます。中断は `phase: cancelled` で区別します。

APK取得には `app_update.state` の同じランダムIDで、`reason_code` 200=検証情報取得、201=APK取得・サイズ確認、202=SHA-256照合、203=インストール用ファイルの確定、の開始と結果も記録します。通信が成功した後の検証エラーも区別できます。

ホスト名・IPアドレス・URL・ヘッダー・証明書・ファイル名・本文・例外の文言は、この共通ログへ渡しません。記録処理が失敗しても通信を止めません。

接続監視中は、ネットワークの種類やAndroidの検証結果が変わったときだけ `state` の `reason_code: 110` を記録します。`from` は0=なし、1=モバイル、2=Wi-Fi、3=Ethernet、4=VPN、5=その他、`online` はインターネット接続能力、`accepted` はOSの接続検証結果、`to` は従量制扱いなら1、`status` はAndroidのバックグラウンドデータ制限の値です。SSID、通信事業者、ネットワーク識別子、IP、位置情報は記録しません。OSの検証結果だけで通信不能と判断する処理は追加しません。
