# フィードバックの送信保留

ログイン済みのアカウントでフィードバックを送信すると、まず本文・タイトルと、選択したログ・画像・チャットコピーを端末に暗号化して保存します。サーバーに接続できない場合や、送信に失敗した場合は保存を残し、保留したことを表示します。端末への保存に失敗した場合は入力欄を消しません。返信は従来どおり、サーバーへの接続が必要です。

ログイン情報があれば、接続の状態表示にかかわらず送信を試みます。再送は、アプリを開いている間の定期的な接続確認の前、通常の通信が成功して接続が復帰したとき、接続先のネットワークが利用可能になったときに行います。接続確認の失敗だけを理由に再送を止めません。通信失敗・サーバー障害時は30秒から最大10分まで待ち時間を倍増し、再起動や通信復帰でも待ち時間を維持します。HTTP 400・404・409・413・422で拒否された送信は自動再送を停止し、内容を端末に保持します。削除済みの送信先や期限切れの添付を繰り返し送信しません。停止中・再試行待ちの項目があっても、ほかのフィードバックの送信は続けます。アプリを終了しても保留した内容は残り、次回起動・復帰後も再送します。アプリが閉じている間のバックグラウンド送信は行いません。ログインが切れた場合は、同じ接続先・アカウントにログインし直すまで保留します。別のアカウントや接続先には送信しません。

本文が受理されたときのフィードバックIDと、添付の送信済み段階を端末に保存します。添付だけが失敗した場合は、その段階から再開します。サーバーが受理した直後に応答が届かなくなった場合など、端末が受理を確認できなかったときの重複は完全には防げません。

選択した画像と端末だけにあるチャット添付は、送信操作時にコピーします。チャットのサーバー側の記録は、サーバーがフィードバックを受け付けた時点でコピーします。接続できない間のチャットコピーには、端末にある履歴・キャッシュを使います。

保存先はアプリ専用のバックアップ対象外領域です。本文と添付をAndroid Keystoreの鍵で暗号化し、接続先とアカウントごとに分けます。送信と添付のアップロードが完了したら保留データを削除します。保留中は自動削除せず、アプリのデータを消去すると失われます。

ログは、フィードバックで添付を選択したものだけを送信操作時にコピーします。この明示的な添付コピーは保留中のフィードバックとともに保持します。通常の操作ログの収集同意・保存期間は変更しません。サーバー調査ログはサーバーが受け付けた時点の同意と保存期間に従います。送信保留・再送開始・完了は、操作ログ収集が有効な場合に既存の `change` イベントへ記録します。再送失敗は既存の `error` イベントへ記録し、HTTP状態、再送するかどうか、次回までの待ち時間も残します。記録するのは段階・結果・例外の分類などで、本文・画像・ファイル名・接続先・認証情報は含めません。

再起動後の保存内容・送信進捗の復元、アカウントと接続先の分離、添付の暗号化コピー、保存失敗時の後始末、サーバー障害後の再送、添付失敗時に本文を再送しないことの単体テストを用意しています。AndroidのビルドとテストはGitHub Actionsで実行し、実機での通信遮断・復帰確認も必要です。
