# V4.8.564 (2026-05-29)

## ロールバック: changelogボタン仕様変更の完全撤回とバージョン混在の解消

### 問題の経緯
- V4.8.559 にて「サイドバーの更新履歴ボタンを専用モーダルに変更（ページ遷移廃止）」を実施
  - ボタンクリックで in-app `#changelog-modal` を表示
  - pushState で URL を `/changelog` に変更、popstate 対応
  - /changelog ルートを chat.html レンダリングに変更（standalone ページ廃止）
  - 大規模 JS (chat_core.v4.8.559.js 等) + CSS 追加
- V4.8.560 / 561 で「root `/` で動作しない」問題の修正を試みたが、chat.html 末尾 IIFE への関数移動など複雑化
- 結果として以下の深刻な混在状態が発生
  - ロールバック後もモーダルコードとv559〜563の資産が残り、表示内容と実装が一致していない状態
  - テンプレートの tailwind CSS が v4.8.558 ハードコードのまま、SYSTEM_VERSION との乖離
  - /changelog アクセス時に期待と異なる UI（フルチャット＋モーダル）が表示される
  - バージョン資産ファイルの乱立により、キャッシュ/CDN トラブル時の原因特定が困難

### 対応内容
- V4.8.558（問題発生直前）の安定した実装へ復帰
- ボタンを従来仕様に戻す（`<button onclick="location.href='{{ url_for('changelog') }}'" ...>`）
- `templates/changelog.html`（standalone フルページ版）と `/changelog` ルート（`render_template('changelog.html')`）を復活
- 実験で生成された v4.8.559 〜 v4.8.563 の全バージョン付き JS/CSS/md を削除
- テンプレート内のハードコードされていた tailwind リンクを v4.8.564 に更新
- V4.8.564向けの静的資産をV4.8.558相当の内容から再作成

### 影響
- 更新履歴は再び別ページ `/changelog` として表示（モーダル不要、履歴の深リンクも従来通り）
- 過去の V4.8.559〜563 資産は二度と使用されない（CDN キャッシュも purge 済み）
- バージョン管理の整合性が完全回復（全アセットが SYSTEM_VERSION と一致）

更新履歴ボタンは、独立した `/changelog` ページへ移動する従来の動作へ戻りました。
