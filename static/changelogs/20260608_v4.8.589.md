# 更新履歴 (V4.8.589) - 2026-06-08

## 変更内容
- **更新履歴の表示順序改善**:
    - `/changelog` および `/api/changelogs` のソートロジックを変更。
    - 従来はファイル名の日付（date_key）を第一優先でソートしていたため、ファイル名の日付が新しい古いバージョン（例: 20260605_v4.8.583）が、バージョン番号が高い最新エントリ（V4.8.588など）より上に表示される問題があった。
    - 新しいソートでは**バージョン番号（ver_nums）を第一優先**、日付を第二優先に変更。これにより、常に最新バージョンの更新履歴がリストの先頭近くに表示されるようになりました。
    - 同バージョン内では日付の新しいものが優先されます。

## 技術的な変更
- `app.py` の `_get_changelogs` 関数内の `files.sort` キーを `(ver_nums, date_key)` に変更（降順）。
- `app.py` の `APP_VERSION` を `2026-06-08-001`、`SYSTEM_VERSION` を `V4.8.589` に更新。
- `chat_core.v4.8.589.js` / `chat.custom.v4.8.589.css` / `chat.tailwind.v4.8.589.css` を新規作成（前バージョンからコピー、機能変更なし）。
- `static/changelogs/20260608_v4.8.589.md` を新規作成。
- 旧 v4.8.588 資産は削除（AGENTS.md の「最新バージョンのみ保持」ルール遵守）。
- サービス再起動 + Cloudflare CDN キャッシュ全削除 + git commit/push 実施。バージョン付き静的ファイルの curl 200 確認済み。

この変更により、ユーザーが更新履歴を確認した際に「一番上に今回のバージョンが出ていない」ように感じる問題が解消されます。
