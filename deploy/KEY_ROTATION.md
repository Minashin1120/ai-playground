# 暗号化鍵のローテーション手順

この文書は、本アプリが保存時に使う暗号化鍵（`secret.key`、Fernet 鍵）を**安全に**別の鍵へ切り替える手順を説明します。

## 対象

- 既定のインストール先 `/opt/ai-playground`（リポジトリをクローンした場所）
- systemd ユニット名: `ai-chat.service` と `ai-chat-worker@1..2.service`（メモリ負荷対策でワーカーは2つのみ有効）
- 前提: 通常どおり運用中であり、起動時に `secret.key` が生成されていること

## 重要な考え方

- 本アプリは `secret.key` を起動時に読み込みます。加えて `secret.key.rotated.*` を**履歴鍵**として読み込みます（新→旧の順で復号を試す）。そのため、**生成した新鍵と旧鍵の両方が残っていれば、どの時点で作業が中断されてもデータは読めます**。
- **ローテーション中・完了後も、作業で作ったバックアップは絶対に自動削除しません。** 指示があるまで保持してください。
- 既に暗号鍵が合わず読めないデータ（孤立データ）は、ローテーションの**対象外**とし、そのまま残します（悪化させない）。

## 手順

### 1. 作業開始前に必ずバックアップする

ローテーション対象は次のとおりです。**これらを先に退避し、指示があるまで削除しない**でください。

| 対象 | 内容 |
|---|---|
| アップロードファイル | `instance/uploads/` |
| データベース | 全テーブルのダンプ |
| ローテーション前の鍵 | `secret.key` のコピー |
| ローテーション後の鍵 | ローテーション完了直後に `secret.key` のコピー |

> ローテーション用スクリプトが自動で退避します（`--execute` 実行時に `backups/rotate-<日時>/` 直下へ）。

### 2. サービスを停止する

再暗号化スイープ中に書き込みが競合しないよう、一時停止します。

```bash
sudo systemctl stop ai-chat.service ai-chat-worker@1.service \
  ai-chat-worker@2.service
```

### 3. 事前確認（ドライラン）を行う

```bash
cd /opt/ai-playground
venv/bin/python scripts/rotate_encryption_key.py --dry-run
```

「既に読めないデータが何件あるか」が表示されます。これらはローテーションでは復旧できず、そのまま残ります。

### 4. ローテーションを実行する

```bash
venv/bin/python scripts/rotate_encryption_key.py --execute --yes
```

スクリプトは次の順で進みます。

1. バックアップ作成（アップロード・DB・ローテ前鍵）
2. 事前検査（現行鍵で読める全データを確認）
3. **新鍵を生成して即保存**し、旧鍵を `secret.key.rotated.<日時>` として保持
4. 読める全データを新鍵へ再暗号化（読めない孤立データはスキップ）
5. 新鍵で全データを検証
6. ローテ後鍵をバックアップ

もし途中で失敗しても、**新旧両鍵がディスク上に残っている**ため、データは失われません。手順どおり DB と鍵を退避から復元すれば元の状態へ戻せます。

### 5. サービスを再起動して確認する

```bash
sudo systemctl start ai-chat.service ai-chat-worker@1.service \
  ai-chat-worker@2.service
curl -fsS https://<あなたのドメイン>/api/version
```

アプリが起動し、`/api/version` が返れば完了です。

### 6. 完了後の状態

- `secret.key`: 新しい鍵（暗号化に使用）
- `secret.key.rotated.<日時>`: 旧鍵（復号のフォールバックとして保持。**削除しない**）
- `backups/rotate-<日時>/`: 作業で作ったバックアップ一式（アップロード・DB・ローテ前後鍵）。**指示があるまで削除しない**

## 旧鍵の扱い（任意）

十分に時間が経ち、全データが新鍵へ移行済みであることを確認できたら、旧鍵は履歴鍵として残したまま、安全な場所へ保管してください。`secret.key.rotated.*` を消すと、まだ旧鍵で暗号化されたデータ（あれば）が読めなくなるため、**削除は慎重に**行ってください。

## 注意

- **自動（スケジュール型）ローテーションは行いません。** 必ず上記の手順を手動で実施し、前後でバックアップと検証を行ってください。
- 鍵が失われると、保存済みのAPIキーや暗号化済みコンテンツは復号できません。**バックアップを破棄しない**ことが最も重要です。
